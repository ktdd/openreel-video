# Phase 0 compatibility fixtures

All data is synthetic and contains no real credentials, conversations, provider results, or user media. Fixture timestamps and IDs are fixed. Do not regenerate legacy JSON from current application defaults: its purpose is to remain an old input as readers/migrations change.

## Core project documents and media

Directory: `packages/core/src/test/fixtures/ai-removal/`.

| File/input | What it represents | Expected behavior after removal |
| --- | --- | --- |
| `ordinary-project.json` | Project schema 1.2.0; a 3-second tone trimmed to source seconds 0.5–2.5, a marker, and a manual caption | Preserve media/clip IDs, trim, volume, captions and marker; portable edit sharing still works. |
| `media.ts` → `createFixtureWav()` | Real RIFF/WAVE PCM: mono, 8 kHz, 16 bit, 440 Hz, 3 seconds, 48,044 bytes | Usable local test media without FFmpeg, Python, codecs, inference or a downloaded fixture. |
| `captions.srt`, `captions.vtt` | Equivalent supplied captions spanning seconds 0–1 and 1–2 | Both formats remain importable/editable without transcription. |
| `completed-generation.svg` | A local 16×16 SVG, 176 bytes, standing in for an already-completed generation | Preserve the local blob and references without invoking a provider. The file is hand-authored, not generated by a live AI service. |
| `legacy-ai-project.json` | Combined pre-removal project, described below | Normalize old live features safely while retaining completed content. |

`legacy-ai-project.json` contains independent cases identified by stable IDs:

- **Completed asset:** media `completed-image`, clip `completed-clip`, source file `completed-generation.svg`. The JSON intentionally has no blob because project JSON omits blobs; tests relink the local SVG and exercise mocked storage save/load. Loading JSON alone should show an ordinary missing-file placeholder, not pretend the media bytes are embedded.
- **Pending generation:** media `pending-image`, clip `pending-clip`, task `synthetic-task-pending`, `isPending: true` and no local blob. After removal, keep references and present local relinking; never poll/retry/generate automatically.
- **Failed generation:** media `failed-image`, clip `failed-clip`, task `synthetic-task-failed`, `kieaiError: true`. After removal, no provider retry affordance; use ordinary placeholder behavior.
- **Existing captions:** subtitle `supplied-caption` with word timing, plus title metadata with Whisper provenance. Text/timing stays useful without its original transcription backend.
- **Removed live effect:** title `legacy-behind-subject-title`, text “Keep this title visible”, `behindSubject: true`. Future loading/export should warn and render normally without requesting a person mask. Phase 0 only captures the input, not that future migration.
- **Saved shader:** definition `ai-phase0-saved-fill` with GLSL 300 ES and an `amount` parameter, referenced by motion text `saved-shader-text`. Preserve definition, parameter and reference. Phase 0 checks persistence/binding, not actual GPU compilation.
- **Creation/motion:** scene `creation-scene`, box recipe `box-asset`, object `creation-box`, render binding `creation-binding`, composition `creation-composition`, layer `creation-layer`, render object `render-box`, and timeline motion instance `creation-instance`. Keep manual scene editing, binding/sync and rendering; the `agent-created` provenance tag must not make the scene disposable.

Tests: `packages/core/src/test/ai-removal-fixtures.test.ts`. They use the production project reader, portable-edit helpers, caption parser, creation validator and binding resolver. Network, worker creation and IndexedDB opening are stubbed to throw. Storage persistence tests mock only the storage boundary; no real user databases are touched.

To materialize the audio for optional manual import:

```sh
mkdir -p .cache/ai-removal-phase0
bun -e 'import { createFixtureWav } from "./packages/core/src/test/fixtures/ai-removal/media.ts"; await Bun.write(".cache/ai-removal-phase0/tone.wav", createFixtureWav());'
```

These are full project documents, **not** portable `openreel-edit` documents. Tests convert the ordinary fixture to portable edit format explicitly. They are not a codec/video/GPU export test suite; the user's HAR supplies a separate manually exercised video workflow.

## Persisted browser state

Input: `apps/web/src/test/fixtures/ai-removal-browser-state.json`.

- `localStorage`: version-7 settings, version-3 UI state, version-1 chat history, and version-0 pending/failed Kie.ai task envelopes. Values are objects; stringify each value before placing it in a disposable test localStorage.
- `olderLocalStorage`: version-6 compatible-provider settings and version-1 UI preferences to exercise existing migrations.
- Manual preferences intentionally differ from defaults: autosave disabled, interval 9, Finnish language, dark theme, waveforms disabled. Future cleanup must preserve them.
- UI inputs include the retired `ai` inspector tab and visible `agentChat` panel.
- The `.invalid` endpoint, voice/model/task/conversation IDs are synthetic. No provider client is created to use them.
- `phase0-unrelated-preference` is an unrelated localStorage sentinel that must survive future cleanup.
- `indexedDB` describes `openreel-secure`/`secrets` record shapes for the five configured provider IDs plus `phase0-unknown-secret`. Ciphertext bytes are deliberately **not valid encrypted credentials**: they test deletion by record ID without decryption. Convert `encryptedData` to an ArrayBuffer and `iv` to Uint8Array if a later IndexedDB test needs to seed them. Do not test decryption with these placeholder bytes.

Tests: `apps/web/src/test/ai-removal-fixtures.test.ts`. They hydrate only settings and UI stores, preserving manual preferences and checking task/project reference integrity. They deliberately do not import the task/chat stores, mount `App`, launch pollers, or open real IndexedDB. Cleanup/idempotency/blocked-storage behavior is future Phase 1 work, not something Phase 0 claims to implement.

**Do not seed these pending tasks into your normal editor profile while the old poller still exists.** Use unit-test storage or an isolated browser profile with network interception for later browser tests. Preserve the JSON inputs when removing provider/task types; tests may need to inspect legacy fields through raw records rather than import removed TypeScript types.
